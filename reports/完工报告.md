## 3. 反编译方法与产物

1. **解包**：用 PyInstaller 自带的 `CArchiveReader` / `ZlibArchiveReader` 解析 cookie + TOC，导出 1407 个 PKG 条目与 743 个 PYZ 模块（`guit-re/extracted`、`guit-re/work`）。
2. **还原 pyc**：PYZ 条目是裸 marshal，按 3.13 头（magic `f30d0d0a` + 12 字节字段）补齐得到合法 `.pyc`。
3. **反编译**：`Decompyle++ v0.6.0`（Rust 重写版 `pycdc`，支持 3.13）+ `pycdas` 反汇编器（作为**唯一真相**用于逐条核对）。
   - 也试了 `byteripper`（Python 实现）作为第二意见，但其对 3.13 还原不完整（`app.py` 只还原出 359 行 vs 真实 811 行），**未采用**，仅用于抽查。
4. **产物**：`guit-re/src/*.py`（6 个模块，共 ~1700 行，全部 `ast.parse` 通过）；后续工作副本为 `<本机路径>
5. **保真度门禁**（`guit-re/fidelity.py`）：把反编译源码用 3.13 重新编译，与 exe 内原始代码对象**逐层比对**——指令流（opname + 语义化 argval，跳转目标规范化为指令序号）、`co_names`、`co_varnames`、`co_argcount`、`co_flags`、`co_freevars/co_cellvars`、常量集合、子代码对象集合；忽略行号类噪声（`__firstlineno__`、`co_firstlineno`）。

## 4. 运行与测试环境重建

- **解释器**：从 exe 解出的 `python313.dll` + `python313.zip`（外补）组成 3.13.16；把解出的 `*.pyd/*.dll`（含 `_tkinter.pyd`、`_tcl_data`、`_tk_data`）与纯 Python 包（PIL/numpy/cv2/onnxruntime/ddddocr/pystray）按 site-packages 布局拼装 → `guit-re/tools/py313/python.exe`，`TCL_LIBRARY`/`TK_LIBRARY` 指向 `_tcl_data`/`_tk_data`。
  - **踩坑**：PyInstaller 把 Tcl/Tk 脚本放在 `_tcl_data`/`_tk_data` 而不是 `lib/tcl8.6`，不设环境变量时 Tk 初始化会以 *"Tcl wasn't installed properly"* 失败；已写入 `tests/support.py`，测试不再依赖 cwd。
- **测试 harness**（`tests/support.py`，全部沙箱化）：
  - **模拟 ASP.NET 门户**（ThreadingHTTPServer）：`__VIEWSTATE/__VIEWSTATEGENERATOR/__VIEWSTATEENCRYPTED/__EVENTVALIDATION` 隐藏字段、控件默认值（`TextBoxISP=自动选择`）、验证码与 `ASP.NET_SessionId` 绑定且换码即失效、登录成功仍是登录页样式但含「联网成功!」、注销 POST 响应渲染**提交前**旧状态（实测行为）、外网探测目标始终可达（白名单模拟）、可切换 `status_unknown` 走探测兜底。
  - 临时配置目录（`config_store.app_dir` 重定向）、随机单实例端口（`GUIT_INSTANCE_PORT`）、`autostart.startup_dir` 重定向到临时目录、`portal_client.ONLINE_PROBES` 收敛为本地。
- **取证工具**：`shot.ps1`（**DPI 感知**的窗口截图，PrintWindow）、`e2e_probe.py`（真实 HTTP 打模拟门户）、`perf_ab.py`（启动耗时中位数）、`accept.ps1`（一键验收）。
  - **踩坑**：非 DPI 感知的截图进程会被 Windows 虚拟化，`GetWindowRect` 返回缩小坐标，**截出的图看似"界面被裁切"**（我一开始据此误判为程序缺陷，已更正并撤回）。加 `SetProcessDpiAwareness(2)` 后截图与真实窗口一致。

## 5. 代码结构与调用链（摘要）

完整清单见 `docs/STRUCTURE.md`（由 `guit-re/analyze.py` 直接从原始字节码提取：函数 / 起始行 / 指令数 / 关键调用 / 跨模块调用边）。

**主流程（GUI 连接）**
```
main()  ── argparse(--silent/--autostart/--console)
        ├─ 单实例：绑定 127.0.0.1:SINGLE_INSTANCE_PORT，占用则连回第一实例 sendall(b'show') 并 os._exit(0)
        ├─ SetProcessDpiAwareness(1)
        ├─ --silent → run_silent()（load_config → has_credential → auto_login → toast）
        └─ tk.Tk() → LoginApp(root, auto_connect)
              _build_ui() 建立控件与事件绑定
              _pump_queue() (after 120ms 循环) ── _handle(msg) ── _append_log/_set_status/_update_net/_set_busy/_show_captcha/_finish
              after 150ms → _on_start() → 回填配置/自启状态 → after 200ms → _start_prefetch()（线程）
              按钮：连接→_on_connect / 断开网络→_on_logoff / 换一张→_refresh_captcha / 隐藏→_on_hide / 退出→_on_quit
```

**登录（后端）**
```
LoginApp._on_connect → _collect_form(校验+保存) → 线程 _worker
   └─ LoginSession.needs_login()      # 以门户状态为准（外网探测不可信）
      └─ PortalClient.query_status() → _request(GET logoff) → _parse_status()
   ├─ 手动码：_submit_manual → LoginSession.submit → PortalClient.submit
   └─ 自动码：_auto_flow → session.prepare()（open_session + fetch_captcha）
              → OcrEngine.classify() → session.submit(guess) → PortalClient._judge()
              验证码错 → 换码重试（maxCaptchaRetry）
```

**断开网络**
```
_on_logoff → 线程 _logoff_worker → session.prepare_logoff()（注销页自己的 ViewState + 取码 + 状态）
   → submit_logoff → 含「验证码」判错 / 成功文案 / 门户状态
   → _confirm_offline：门户状态优先（未联网 → 立即成功），否则最多 3 次外网探测；不谎报失败
   → 成功后 invalidate_form()（注销页与登录页 ViewState 不通用）
```

**静默模式**：`run_silent()` → `auto_login()` → 识别成功提交 / 识别失败返回 3 → 主流程转 GUI 手输。
**单实例**：`_instance_listener` 收到 `show` → 回 `ok` → 主线程 `deiconify`。

### 6.3 工具链/环境坑（本次工作中踩到并已固化为文档）

1. **Tcl 库路径**：3.13 运行时需 `TCL_LIBRARY/TK_LIBRARY` 指向 `_tcl_data/_tk_data`，否则 Tk 起不来。
2. **截图进程 DPI 虚拟化**：非 DPI 感知进程拿到的窗口坐标是虚拟化的，会得出"界面被裁切"的错误结论（已更正、已撤回对 subagent 的错误要求）。
3. **PyInstaller onefile 子进程**：窗口属于 bootloader 的**子进程**，按父 pid 找 `MainWindowHandle` 永远为 0；截图脚本改为轮询同名进程。
4. **3.14 的 `dis` 不能解 3.13 字节码**（会抛 `IndexError`），必须用 3.13 解释器做反汇编/保真度比对。
5. **`Start-Process -RedirectStandardOutput` 在本机环境报 `NO_PROXY/no_proxy` 重复键**，改用直接调用/输出重定向到文件规避。
6. **Windows PowerShell 5.1 读 `.ps1` 用 ANSI 代码页**：脚本里的中文会被误读成乱码甚至引发语法错误 → 验收脚本改为纯 ASCII。

   - T3（P0）：`test_instance` 用"占端口但不应答"的第一实例，证明当时的还原会让 `import app` 崩（当前代码 FAIL / 独立基线 PASS），已要求并确认修复。
   - T4（P1）：用两个实验推翻"Tk Label width 单位是字符、会暴涨到 2566px"的前提，并指出 `_fit_window()` 会用 `root.geometry()` 锁死窗口几何 → 已撤回。
   - T5：用 `sys._current_frames()` 线程栈定位 GUI 用例次序相关失败的根因（卡在 `ssl -> _load_windows_certs`），进而发现 **`PortalClient` 每次都重建 SSL 上下文/读 Windows 证书库** 的产品侧隐患，修复后 GUI 用例连跑三轮 15/15 全绿、构造路径反而更快。
   - T6：用两线程并发实验复现 `OcrEngine.available()` 的初始化竞态（`[False, True]`），并对齐前端报告的 R3（首次 `import ddddocr` 期间用户点击会被误判"OCR 不可用"）→ 加锁后 `[True, True]`。
4. **自我纠错**：我早期据截图误判"界面被裁切"，实为非 DPI 感知截图进程的虚拟化伪影；已修正工具与判据，并撤回对 subagent 的错误要求（见 §6.3）。

### 10.4 用例的确定性

- 所有网络交互都指向本机模拟门户（`ThreadingHTTPServer`），`OnlineProbes` 被收敛；`autostart` 的启动文件夹、配置目录、单实例端口均重定向到临时路径/随机端口。
- 时间相关断言留有余量（如"门户确认下线 < 1 s"、"注销整体 < 3 s"、"探测早退 < 0.5 s"）。
- 修掉了一处**测试自身的顺序污染**（两条后端用例把 `pc.time.sleep` 猴子补丁泄漏给后续用例）与一处**测试前置依赖**（GUI 用例等了 0.6 s 就断言预取结束），并把 GUI 用例连跑 3 轮验证确定性。

## 12. 风险、局限与未做事项

### 12.1 局限（无法在本机消除）

1. **未对真实门户 `http://10.6.6.6` 联调**：没有校园网凭据，也无法从本机访问该内网地址。协议行为依据是：源码注释里记录的实测结论（ViewState 家族、验证码与会话绑定、注销 POST 返回旧状态、外网探测白名单）+ **用原始 exe 打自建模拟门户成功**（§10.2）双向印证。
2. **OCR 只能用合成验证码验证**：ddddocr 的模型针对真实门户验证码训练，读不出我生成的合成图（实测识别为 `3aaa/abaa/hbaa`）。因此验证的是"引擎能加载/能返回结果/识别错误时正确换码重试并最终转手输"这条链路，而不是"识别率"。
3. **平台依赖**：DPI 感知、单实例回环端口、启动文件夹 `.lnk`、`Shell_NotifyIcon` 托盘行为都只在当前 Windows 机器上验证过。
4. **未重新打包成 exe**：本机没有可用于 3.13 的 PyInstaller（内嵌运行时无 pip），且重新打包不是本任务的交付要求。若要产出可分发的单文件 exe，需在与原程序一致的 3.13 环境下执行 `pyinstaller --onefile --windowed --add-data "assets;assets" app.py`（需按原程序补齐 `ddddocr/onnxruntime/cv2` 等 hook 与 `_tcl_data/_tk_data` 资源）。
5. **冻结 exe 的启动耗时不可直接对比**：原 exe 冷启动 4.83 s 中绝大部分是 onefile 解包（86 MB），源码态的 50~90 ms 只是同一量级的程序自身开销。

### 12.2 有意保留（经评估不改，避免"多余改动"）

| 项 | 现状 | 为什么不改 |
|---|---|---|
| 门户页面编码仅按 UTF-8 解码 | 遇 GBK/BOM 页会退化为"未知/未确认"，不会误判成功 | 属行为变更，方向安全（宁可报"未确认"也不谎报成功），需真机门户样本才能定论 |
| 未做配置 schema 校验 | `cfg['fields']` 被手改坏时由 GUI 兜成"内部错误：…" | 极端场景；加校验会改变非法配置的可见行为 |
| 源码模式自启项判定 | `.lnk` 指向同一 `pythonw.exe` 时不重建 | 与原语义一致；打包/源码两种模式的期望需要产品决策 |
| 密码明文存本机 `config.json`（勾选"记住密码"时） | 原设计如此，且声明"仅存本机" | 门户本身是 HTTP，加密意义有限；改加密会破坏与原版的配置兼容 |
| 单实例回环端口无鉴权 | 本机任意进程可发 `show` 让窗口弹出 | 无实质危害；加鉴权属多余复杂度 |
